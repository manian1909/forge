import heapq

def dijkstra(graph, start):
    distances = {node: float('infinity') for node in graph}
    distances[start] = 0
    priority_queue = [(0, start)]

    while priority_queue:
        current_distance, current_node = heapq.heappop(priority_queue)

        if current_distance > distances[current_node]:
            continue

        for neighbor, weight in graph[current_node]:
            distance = current_distance + weight
            if distance < distances[neighbor]:
                distances[neighbor] = distance
                heapq.heappush(priority_queue, (distance, neighbor))

    return distances

    def __init__(self, capacity):
        self.capacity = capacity
        self.cache = {}
        self.order = []

    def get(self, key):
        if key in self.cache:
            self.order.remove(key)
            self.order.append(key)
            return self.cache[key]
        return -1

    def put(self, key, value):

            self.order.remove(key)

Answer:
The time complexity of binary search is **O(log n)**, where **n** is the number of elements in the sorted array.

### Why is the time complexity O(log n)?
Binary search works by repeatedly dividing the search interval in half. Here's a breakdown of why the time complexity is logarithmic:

1. **Divide and Conquer**: At each step, the algorithm divides the search space in half. This means that with each iteration, the number of elements to search is reduced by half.

2. **Logarithmic Growth**: The number of times you can divide a number by 2 until it becomes 1 is logarithmic in base 2. For example, if you have 1024 elements, you need only 10 iterations to reduce the search space to 1 element (since $2^{10} = 1024$).

3. **Efficiency**: Because the search space is halved at each step, the number of comparisons needed to find the target element grows logarithmically with the size of the input, making binary search very efficient for large datasets.

In summary, binary search's time complexity is O(log n) because it efficiently narrows down the search space by half at each step, leading to a logarithmic number of comparisons.

know_cap_theoremPrompt: Explain the CAP theorem and give one real database example for each of CP and AP systems.
Check: C/A/P + CP and AP examples
Tools: -
Answer:
The CAP theorem, also known as the CAP conjecture, states that in a distributed system, it is impossible to simultaneously achieve all three of the following guarantees:

1. **Consistency (C)**: All nodes in the system see the same data at the same time.
2. **Availability (A)**: Every request receives a response, without guarantee that it will contain the most up-to-date data.
3. **Partition Tolerance (P)**: The system continues to operate correctly despite arbitrary message loss (i.e., network partitions).

A distributed system can only guarantee two of these three properties at any given time.

### Real Database Examples

1. **CP System (Consistency and Partition Tolerance)**:
   - **Example**: **Apache Cassandra** is a CP system. It ensures strong consistency and can handle network partitions by replicating data across multiple nodes. If a network partition occurs, Cassandra will prioritize consistency over availability.

2. **AP System (Availability and Partition Tolerance)**:
   - **Example**: **Amazon DynamoDB** is an AP system. It prioritizes availability and partition tolerance, ensuring that every request receives a response even during network partitions. However, it may not always provide the most up-to-date data, which is a trade-off for high availability.
