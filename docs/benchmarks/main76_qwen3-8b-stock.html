Here is the Python function `dijkstra` that computes the shortest distances from a start node to all reachable nodes in a graph:

```python
def dijkstra(graph, start):
    import heapq
    distances = {node: float('infinity') for node in graph}
    distances[start] = 0
    priority_queue = [(0, start)]

    while priority_queue:
        current_distance, current_node = heapq.heappop(priority_queue)

        if current_distance > distances[current_node]:
            continue

        for neighbor, weight in graph[current_node]:
            distance = current_distance + weight
            if distance < distances[neighbor]:
                distances[neighbor] = distance
                heapq.heappush(priority_queue, (distance, neighbor))

    return distances
```

Check: O(log n)
Tools: -
Answer:
Binary search has a time complexity of **O(log n)**, where **n** is the number of elements in the sorted array.

### Why is the time complexity O(log n)?

Binary search works by repeatedly dividing the search interval in half. Here's a breakdown of why the time complexity is logarithmic:

1. **Divide and Conquer**: At each step, the algorithm divides the search space in half. This means that with each iteration, the number of elements to search is reduced by half.

2. **Number of Steps**: If you start with **n** elements, after the first step you have **n/2** elements, then **n/4**, and so on. This continues until you either find the target or narrow down the search space to a single element.

3. **Logarithmic Growth**: The number of steps required to reduce the search space from **n** to 1 is **log₂(n)**, which is why the time complexity is **O(log n)**.

This efficiency makes binary search very effective for searching in large sorted arrays.

know_cap_theoremPrompt: Explain the CAP theorem and give one real database example for each of CP and AP systems.
Check: C/A/P + CP and AP examples
Tools: -
Answer:
The CAP theorem, also known as the Brewer's theorem, states that in a distributed computing environment, a system cannot simultaneously provide all three of the following guarantees:

1. **Consistency (C)**: All nodes in the system see the same data at the same time.
2. **Availability (A)**: Every request receives a response, without guarantee that it contains the most up-to-date data.
3. **Partition Tolerance (P)**: The system continues to operate despite arbitrary message loss (network partitions).

A system can only guarantee two of these properties at any given time. 

### Examples of CP and AP Systems

1. **CP System (Consistency and Partition Tolerance)**:
   - **Example**: **Apache Cassandra** is a CP system. It ensures strong consistency and handles network partitions by allowing reads and writes to be directed to the closest node, ensuring data consistency even during partitions.

2. **AP System (Availability and Partition Tolerance)**:
   - **Example**: **Amazon DynamoDB** is an AP system. It prioritizes availability and partition tolerance, ensuring that the system remains operational and responsive even during network partitions, at the cost of eventual consistency.

In summary, CP systems prioritize consistency and partition tolerance, while AP systems prioritize availability and partition tolerance.
