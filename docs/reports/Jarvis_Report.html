Jarvis, piece by piece

Jarvis is a personal assistant that runs on your laptop. A language model you trained yourself (Forge) does the thinking, and a Python program around it gives the model hands: tools, voice, memory and safety rules. This report follows each flow from the keyboard or microphone to the result.

2. The model: how Forge was made

You wanted a model you own. Ollama's stock qwen3:8b acted only as a teacher that wrote training examples. The student, Forge, is Qwen3-8B with small trainable adapters added (QLoRA), trained on Kaggle's free T4 GPU, then shrunk to a 5 GB file that Ollama serves.

  G --> H["forge-open

Training runs on Kaggle because 8B cannot be trained in 4 GB of laptop VRAM.

Fine-tuning

Continue training an existing model on your own examples so it adopts your identity, tool-call format and habits.

QLoRA

The base weights are frozen and stored in 4-bit. Only small low-rank matrices (rank 32) are trained, so 8B fits on a 16 GB T4.

Distillation

A stronger or equal "teacher" writes the examples; the student learns to imitate them.

Loss masking

Each assistant turn is a prompt/completion pair. Loss counts only the completion tokens, so the model learns to answer, not to echo the question.

Quantisation (Q4_K_M)

Weights stored in about 4.5 bits instead of 16. The file shrinks from about 16 GB to 5 GB with a small quality cost.

GGUF + Ollama

GGUF is the single-file format llama.cpp reads. Ollama is only the engine that loads it and serves an HTTP API.

Abliteration

For forge-open: find the direction in the activations that separates "refuse" from "comply" and subtract it from the weights. Refusals dropped from 56% to 0% on harmful prompts in the Kaggle check.

Checkpointing

Training saves every 50 steps. An earlier crash after a long eval lost 77 minutes, hence the rule.

3. What happens to one request

This is the main path. Typing and speaking end up in the same place, so one set of rules covers both.

sequenceDiagram
  actor U as You
  participant T as TUI
  participant Q as Quick commands
  participant S as Skills + Experience
  participant A as Agent
  participant L as LLM stack
  participant B as Toolbox
  participant J as Jail / OS
  U->>T: "make an excel of my expenses"
  T->>Q: parse(text)
  alt matches "next song", "volume 40%" ...
    Q->>J: press media key / set volume
    Q-->>T: short reply (no model used)
  else not a quick command
    T->>S: match skills, recall similar task
    S-->>T: recipe notes + one working example
    T->>T: context over 85%? then /compact first
    T->>A: run(text, hints)
    loop until final answer
      A->>L: chat(messages, tool schemas)
      L-->>A: text or tool_call
      A->>B: call(tool, args)
      B->>J: run inside the jail
      J-->>B: output
      B-->>A: result string
    end
    A-->>T: answer
    T-->>U: shown, optionally spoken
    T->>S: if it worked, save the steps
  end

The conversation is kept as a list of messages; each loop turn appends the model's message and the tool result.

4. The agent loop and its safety nets

An agent is a loop: ask the model, run the tool it asked for, show it the result, repeat. An 8B model slips often, so the loop adds checks around it.

5. Tools and the sandbox

Tool calling means the model emits a structured request ({"name": ..., "arguments": ...}) instead of prose. Jarvis runs it and returns the result as text. Every tool returns a string, even on error, so the model always sees what happened.

The jail: operating-system enforced, not text-checked

Windows labels every process with an integrity level. A low process cannot write to anything not labelled low, cannot use admin rights, and cannot approve a UAC prompt. Jarvis labels one folder low and starts every command with a low-integrity copy of your own token. Redirects, child processes and Python are all covered because the OS refuses the write, whatever the command looks like.

flowchart LR
  M["Model writes a command"] --> I{"Install or admin
command?"}
  I -- yes --> X1["Refused before running"]
  I -- no --> L["jail.run_low(): process with low-integrity token"]
  L --> RD["Read anywhere on the PC: allowed"]
  L --> WR{"Write target"}
  WR -- "inside Downloads/jarvis" --> OK["Allowed, no prompt"]
  WR -- "anywhere else, registry" --> DEN["Windows: access denied"]
  DESK["Desktop actions
(open Chrome, Outlook, volume)"] --> OUT["Run in Jarvis's own process:
fixed, narrow inputs only"]

Chrome and Outlook cannot run inside the jail (they need their own profile), so those actions live outside it and accept only a search text, app name, URL or mail.

Not covered: a Windows UAC prompt that you click "Yes" on yourself. Jarvis never requests one, so if one appears unexpectedly, click No.

6. Quick commands: no model needed

An 8B model needs seconds and sometimes invents a PowerShell command that does not exist. For simple, fixed phrases, plain pattern matching is faster and more reliable. The same parser serves typed and spoken text; for speech it tolerates "vol", number words and filler like "please".

flowchart LR
  T["text"] --> N["normalise
(lowercase, number words, filler)"]
  N --> P{"commands.parse()"}
  P -- "next / previous / pause / resume" --> MK["media.press(): Windows media key"]
  P -- "volume up / down / a bit / 40% / mute" --> VL["pycaw master volume
(volume keys as fallback)"]
  P -- "play song" --> PM["find video, reuse the open
YouTube tab, else open one"]
  P -- "open app or folder" --> OA["Start-menu match / folder search"]
  P -- none --> LLM["Hand over to the model"]
  MK --> R["short reply + chime"]
  VL --> R
  PM --> R
  OA --> R

The exchange is still added to the conversation, so "a bit lower" or "what did you play?" make sense afterwards.

9. The context window

The model can only read about 8,000 tokens at once. System prompt, tool definitions, the chat, skill notes and tool output all share that space. Ollama keeps a KV cache (the attention keys and values of tokens already read) so earlier tokens are not recomputed.

pie showData title What shares the 8k window
  "System prompt" : 12
  "Tool schemas" : 18
  "Your messages" : 15
  "Replies" : 20
  "Tool output + skills" : 35

Illustrative split. Run /context for your real numbers.

Flash attention

Computes attention in blocks without storing the full score matrix. Less memory, faster.

q8_0 KV cache

Cache stored in 8 bits instead of 16, roughly halving its memory.

num_gpu = 22

22 transformer layers on the 4 GB GPU, the rest on CPU. 24 layers generate faster (12.6 tok/s) but reading prompts becomes 4x slower, and every tool result is new prompt text.

11. Standby worker and memory sharing

The model holds about 3.7 GB of RAM and most of the GPU. If you launch a game, Jarvis steps aside and finishes later. Two ideas make that safe: a governor that watches the machine, and a write-ahead task file that saves the conversation before every model call.

stateDiagram-v2
  [*] --> Waiting: worker on standby
  Waiting --> Running: task picked up
  Running --> Paused: free RAM under 1.2 GB, GPU over 15% by another app, full-screen app, or listed game
  Paused --> Unloaded: stop reply, Ollama keep_alive 0
  Unloaded --> Resumed: 4.8 GB free and calm for 30 s
  Resumed --> Running: reload model, continue from saved messages
  Running --> Done: answer written to results
  Running --> Retry: server error, growing wait
  Retry --> Running
  Retry --> Failed: 8 errors in a row
  Done --> Waiting
  Failed --> Waiting

sequenceDiagram
  participant W as Worker
  participant F as tasks/id.json
  participant G as Governor
  participant O as Ollama
  loop each step
    W->>F: save whole conversation
    W->>G: ok to call the model?
    G-->>W: yes
    W->>O: chat
  end
  Note over G,O: a game starts
  G->>O: abort reply, unload model
  O-->>G: RAM and VRAM freed
  Note over G: calm for 30 s
  G->>O: load model
  W->>F: reload last saved state, no tool runs twice

Repeated pauses within 5 minutes double the wait (up to 16 minutes) so it never ping-pongs. /bg task, /jobs, /cancel n and /standby on (start at login) control it. Answers also land in Downloads/jarvis/results.

13. PDFs and images (added today)

Forge reads text only, so pictures are turned into words first. This is the "CNN" part: a small vision model (a vision encoder plus a language head) describes each figure, and Forge explains from that description.

15. Key concepts, quickly

Transformer / LLM

Predicts the next token from all earlier ones using attention. Everything here is built around that one operation.

Token

A word piece. Speed, context and usage are all counted in tokens.

Function calling

The model outputs a structured call; code executes it. Makes a chat model into an agent.

ReAct-style loop

Reason, act, observe, repeat. The agent loop in chapter 4.

Prompt injection

Hostile text inside data trying to give orders. Mitigated by labelling data and blocking side effects.

In-context learning

Showing examples in the prompt changes behaviour without training. Skills and experience use it.

Sandboxing

Limits enforced by the OS (integrity levels), so they hold no matter what code the model writes.

Write-ahead state

Save before acting, so a crash resumes instead of restarting.

Exponential backoff

Wait longer after each failure; used for server errors and repeated pauses.

Voice activity detection

Decide when speech starts and ends relative to background noise.

ASR (Whisper)

Neural speech recognition. Here a small English model for wake words and commands.

TTS

Text to speech; neural online voices or offline Windows voices.

Hybrid inference

Local by default for privacy and cost, cloud when the local model cannot cope.

Vision-language model

A CNN/ViT image encoder feeding a language model, so it can describe diagrams.
